# apartment-search - как класть критерии пользователя на инструменты

Порядок "от грубого к точному". Не начинай с выкачивания выдачи.

## 1. Разложи запрос

| Сказал пользователь | Куда кладётся |
|---|---|
| купить / снять / посуточно / в аренду бизнесу | `deal`: sale / rent / daily / lease |
| квартира, дом, участок, коммерция | `estate` (по умолчанию flat) |
| "Ваке", "Сабуртало", "Ваке-Сабуртало" | `areas` - принимает и микрорайон, и район |
| "у метро Руставели" | `metro: ["Руставели"]` (только Тбилиси) |
| "двушка", "2-3 комнаты" | `rooms: [2, 3]`; 10 означает "10 и больше" |
| "две спальни" | `bedrooms: [2]` - у livo это отдельный от комнат параметр |
| "до 900 долларов" | `price_max: 900`, `currency: "USD"` |
| "до 1500 за метр" | `price_max: 1500`, `price_per_m2: true` |
| "от 60 метров" | `area_min: 60` |
| "новостройка" / "вторичка" | `building: ["new"]` / `["old"]` |
| "с ремонтом" | `conditions` - id из `reference(['conditions'])` |
| "от собственника" | `owner: ["physical"]` |
| "с лифтом" | `amenities: ["elevator"]` |
| "что новенького" | `order: "date_desc"` + фильтрация по `age_days` вручную |

Названия локаций принимаются на любом из трёх языков сайта. При совпадении имени
микрорайон приоритетнее района: `areas: ["Ваке"]` - это микрорайон Ваке, а не район
Ваке-Сабуртало. Не уверен в названии - сначала `geo(city="Тбилиси")` или
`geo(query="ваке")`.

Микрорайоны в таксономии livo есть практически только у Тбилиси (75 из 76 на всю
Грузию). В Батуми, Кутаиси и остальном - фильтруй районами, они же `areas`.

## 2. Посчитай, прежде чем качать

`count` - один дешёвый запрос, показывает, осмысленны ли критерии:

* `total` < 10 - фильтр слишком узкий, предложи ослабить;
* `total` > 2000 - слишком широкий, выдача будет случайной, добавь ограничений;
* сравнивай варианты фильтра между собой, это дёшево.

## 3. Ищи

`search` возвращает `applied_filters` - эхо самого API о том, что он разобрал.
Если фильтровал по району, а там пусто - фильтр не применился, и выдачу показывать
нельзя.

Сортировка не применяется ко всей выдаче: super_vip, vip_plus и vip закреплены сверху
всегда, и внутри тира уже работает `order`. У каждой карточки есть `promo_tier` -
`null` значит обычное объявление. Первые 5-10 позиций почти любой страницы куплены,
поэтому "самое свежее сверху" не работает даже с `order: "date_desc"`.

Сам `date_desc` сортирует по `last_updated`, а не по публикации. Для свежести
смотри `age_days`, а не позицию и не `order`: хочешь "что нового" - возьми больше
карточек и отфильтруй по `age_days` сам.

## 4. Детали - точечно

`listing(id)` - по конкретным кандидатам, не по всей выдаче. Там описание,
удобства, координаты, кадастровый код, просмотры и `published` - настоящая
дата публикации.

## 5. Чего не делай

* Не проси "с лифтом И кондиционером" одним вызовом: несколько `amenities`
  API объединяет по ИЛИ. Нужен И - сделай два `count`/`search` по одному удобству
  и пересеки id сам.
* Не выдавай `updated` за свежесть - это правка или платное поднятие.
* Не считай `total` числом квартир: одно жильё часто висит несколькими объявлениями.

## Что сообщать в ответе

Всегда: сколько объектов показано против `total`; возраст каждого объявления
(`age_days` / `published`); что livo - витрина группы tnet и показывает не весь
инвентарь рынка.
